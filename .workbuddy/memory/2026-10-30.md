
## DoubleDragon 移植：黑屏冻结破案（build69–77）

- **冻结根因**：JPEG 标记扫描器 `sub_82186528` 的流 `size` 是负数（0xFFF5F603，
  end < cur）。此前的"截断到可读范围"让它永远找不到结束标记 → 帧循环被吃住
  （136 帧后永久黑屏）。改为 `size>=0x80000000` 时置 abort → 函数入口 `return 0`。
- **0x40D016D0 真身**：`0x7018E800` 是 jpeg_decompress_struct，`err+0` 是
  error_exit（正常为 `0x821478F0`，末尾 `b 0x82395270` = throw/unwind）。
  recomp 无 SEH 展开 → FixThrow 短路 → 解码器带坏寄存器继续 → `err+0` 被写坏。
  触发条件是格式嗅探器把 PNG 也喂给 JPEG 解码器。
- **修法**：`sub_821497F8` 入口判 FFD8，非 JPEG 直接返 E_FAIL。
- **VM 跳表**：`0x820D799C` 406 项 handler 表（dispatcher `0x820D7FF4`，字节码 VM
  用 `lwzx+mtctr+bctr`）。静态不可见 → 必须写进 manifest 的
  `[entrypoint.functions]` 再 codegen。补 405 项 + 3 个未解析分支目标后清零 FATAL。
- **重要流程**：`generated/**` 不入库；每次 `rexglue codegen` 后必须跑
  `python tools/apply_patches.py` 重打三处补丁（pch 陷阱、86528 abort、497F8 skip）。
- 结果：无头沙箱 50s / 18000+ 帧稳定，13 张图 fmt-OK，8 条 GPU pipeline。
- 备份：`heartbeat_run73.log`（冻结现场）、`PORTING_NOTES.md` 第 13 节。

## 恢复垂直同步（build78）
- 黑屏排查期留下的 `vsync=false` 是"速度变快"的原因：vblank 由 presenter 的
  vsync worker 驱动，关掉后中断按 CPU 速度发 -> 逻辑快进（~360fps）。
- 改为 `OnPreLaunchModule` 里 `vsync=true`（若用户用命令行显式改过则不覆盖），
  保留 `host_present_from_non_ui_thread=true`。
- 实测 60s：58.4fps / 3510 帧，无 FATAL，进程存活。
- 提交 e71bfb5，笔记 PORTING_NOTES.md 第 14 节。

## 按 A 闪退（build82）
- 根因：`0x820EE688` 是 12 字节 jmp thunk，不在 .pdata、没有静态引用，
  地址由调用方 `lis r11,0x820F; addi r4,r11,-0x1978` 现拼 → codegen 不生成 → FATAL。
- 错路（勿再走）：全量"终结指令后即入口"扫描（8222 个）会把函数切断，
  产生上千 Unresolved branch；按未解析分支反推剔除也不收敛。
- 正解：`tools/gen_callback_entries.py` 扫 lis+addi/ori 拼地址；
  `tools/prune_entries.py` 只留短 thunk（≤16 条指令到终结），并逐个写 manifest 跑
  codegen 验证，干净才保留 → 165 候选留 96（含 0x820EE688），函数 10880→10976。
- apply_patches.py 新增"跨函数 goto → 尾调用"，并补 DECLARE_REX_FUNC 声明。
- 状态：标题屏 45s / 57.8fps 稳定。提交 3102fcd，笔记第 15 节。
